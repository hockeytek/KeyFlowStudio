Настройка Cloud GPU для KeyFlow Studio

Эта инструкция описывает полный путь от пустого AWS-аккаунта до рабочего облачного GPU внутри программы. Текст основан на том, что приложение реально делает через AWS API и по SSH. Если какой-то шаг здесь пропустить, часть интерфейса в разделе Cloud (AWS) будет работать не полностью или не будет показывать корректные данные.

Коротко: программе нужен не просто EC2-инстанс, а целая связка: AWS profile с правами, регион, EC2 key pair, security group, GPU quota, публичный или свой AMI, SSH-доступ и, если нужен блок расходов, активированный Cost Explorer.

Что именно использует программа в AWS

Сервис / API Для чего используется Обязателен
EC2 Список инстансов, запуск, остановка, удаление, создание новых GPU-инстансов, поиск AMI, список key pair и security groups. Да
STS Проверка AWS credentials через GetCallerIdentity. Да
Pricing API Показ On-Demand цены текущего типа инстанса. Желательно
EC2 Spot Price History Показ текущей Spot-цены и availability zone. Желательно
Cost Explorer Расходы за месяц, за вчера и прогноз до конца месяца. Нужно, если хотите видеть блок расходов
Service Quotas Чтение квоты на G/VT Spot и On-Demand, чтобы UI показывал только реально доступные GPU-типы. Желательно

Ничего дополнительно разворачивать в AWS, кроме EC2, не нужно. Но аккаунт и IAM-права должны позволять приложению читать цены, квоты и расходы, иначе часть UI будет показывать N/A или ошибки.

Что нужно создать или включить заранее

  1. AWS account с включённым биллингом.
  2. IAM user или профиль с programmatic access.
  3. Access Key ID и Secret Access Key для этого профиля.
  4. AWS CLI на локальной машине или ввод credentials прямо в окне программы.
  5. EC2 key pair в том же регионе, где будет запускаться инстанс.
  6. Security group с открытым SSH и доступом к worker API на порту 8080.
  7. GPU quota в выбранном регионе: отдельно для Spot и отдельно для On-Demand.
  8. Cost Explorer, если хотите видеть расходы внутри программы.

Минимальные IAM-права

Ниже приведён минимальный набор действий, который соответствует реальному коду приложения. Это не единственный вариант, но этого достаточно, чтобы всё отображалось и управлялось корректно.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "sts:GetCallerIdentity",
        "ec2:DescribeInstances",
        "ec2:StartInstances",
        "ec2:StopInstances",
        "ec2:TerminateInstances",
        "ec2:RunInstances",
        "ec2:ModifyInstanceAttribute",
        "ec2:DescribeImages",
        "ec2:CreateImage",
        "ec2:CreateTags",
        "ec2:DescribeKeyPairs",
        "ec2:DescribeSecurityGroups",
        "ec2:DescribeSpotPriceHistory",
        "ec2:DescribeInstanceTypeOfferings",
        "ec2:DescribeInstanceTypes",
        "pricing:GetProducts",
        "ce:GetCostAndUsage",
        "ce:GetCostForecast",
        "servicequotas:GetServiceQuota"
      ],
      "Resource": "*"
    }
  ]
}

Если блок расходов вам не нужен, можно убрать действия ce:*. Если текущая цена в UI не нужна, можно убрать pricing:GetProducts и Spot history, но тогда часть интерфейса перестанет показывать полезную информацию.

Что должно быть в Security Group

Правило Зачем Рекомендация
Inbound TCP 22 SSH для bootstrap worker, проверки окружения и установки watchdog. Открывать только для вашего IP или VPN.
Inbound TCP 8080 HTTP API облачного worker. Открывать только для доверенного IP. Не держать открытым на весь интернет без необходимости.
Outbound all Нужен для apt, pip, Hugging Face, GitHub Releases и health/API вызовов. Обычно оставляют стандартный allow all.
Важно: worker слушает обычный HTTP на порту 8080 и не использует отдельную аутентификацию. Безопасность здесь обеспечивается только security group и ограничением источников доступа.

Какой инстанс выбирать

Приложение хранит собственный каталог GPU-типов и предпочитает современные single-GPU варианты с 24 GB VRAM. Именно поэтому в интерфейсе наверху обычно первыми будут g5 и g6.

Тип GPU VRAM vCPU Комментарий
g5.xlarge NVIDIA A10G 24 GB 4 Базовый рекомендованный вариант. Его использует quick create по умолчанию.
g5.2xlarge NVIDIA A10G 24 GB 8 Хороший вариант, если хотите чуть больше CPU-запаса для worker и ffmpeg.
g5.4xlarge NVIDIA A10G 24 GB 16 Для более тяжёлых пайплайнов и более комфортной фоновой обработки.
g6.xlarge / g6.2xlarge / g6.4xlarge NVIDIA L4 24 GB 4 / 8 / 16 Современная альтернатива, если в регионе есть G6.
g4dn.xlarge / 2xlarge / 4xlarge NVIDIA T4 16 GB 4 / 8 / 16 Устаревшая бюджетная группа. Может не хватать VRAM для части сценариев.
p3.2xlarge / p3.8xlarge NVIDIA V100 16 GB 8 / 32 Старое, обычно более дорогое семейство. Используйте только если в регионе нет лучших вариантов.

С точки зрения самого приложения наиболее прагматичный стартовый выбор: Spot + g5.xlarge для экономии или On-Demand + g5.xlarge / g5.2xlarge для стабильности.

Как работает AMI и какие варианты поддерживаются

1. Предпочтительный вариант: свой AMI KeyFlow Studio

После первого успешного bootstrap лучше создать собственный AMI через контекстное меню инстанса. Программа создаёт AMI с тегами App=KeyFlowStudio и SourceInstanceId=..., а затем ищет такие AMI в первую очередь. Это самый удобный вариант для дальнейших запусков.

2. Автоматический поиск публичного GPU AMI

Если собственного AMI ещё нет, quick create пытается найти публичный Ubuntu 22.04 GPU Deep Learning AMI. Поиск делается по именам, а не по жёстко вшитому AMI ID, потому что AMI ID отличаются по регионам и меняются со временем.

Программа ориентируется на такие шаблоны имён:

  • Deep Learning Base OSS Nvidia Driver GPU AMI ... Ubuntu 22.04
  • Deep Learning OSS Nvidia Driver AMI GPU PyTorch ... Ubuntu 22.04
  • другие публичные AMI с сочетанием GPU + Ubuntu 22.04 + Deep Learning

3. Ручной выбор из списка AMI

Кнопка Выбрать из списка... показывает все AMI, принадлежащие вашему аккаунту в текущем регионе. Это удобно, если вы уже делали snapshot или поддерживаете несколько собственных образов.

Что показывает UI по ценам и откуда это берётся

  • Цена текущего инстанса — текущая Spot-цена или On-Demand цена для выбранного типа.
  • Расходы за месяц / вчера / прогноз — данные из Cost Explorer.
  • Список типов в менеджере — приложение подгружает доступные в регионе GPU-форматы и пытается сразу показать почасовую цену возле каждого.
Важно: точные суммы всегда зависят от региона, availability zone, рыночной Spot-цены и вашего аккаунта. В приложении нет жёстко зашитого прайса. Поэтому если вам нужен актуальный расчёт, ориентируйтесь на то, что показывает AWS API прямо сейчас, а не на старые скриншоты и заметки.

Дополнительные расходы, которые надо учитывать отдельно:

  • EBS-диск инстанса: программа создаёт root volume gp3 60 GB.
  • Публичный IPv4-адрес.
  • Исходящий трафик.
  • Хранение AMI и snapshot'ов после создания своих образов.

Полный путь настройки с нуля

  1. Создайте IAM user или профиль для программы.
    Подготовьте Access Key ID и Secret Access Key.
  2. При необходимости включите Cost Explorer.
    Если этого не сделать, блок расходов в программе будет пустым или будет показывать ошибку.
  3. Проверьте GPU quotas в выбранном регионе.
    Для Spot и On-Demand квоты отдельные. Если нужный тип не появляется в списке, почти всегда проблема в квоте или в отсутствии предложения этого типа в регионе.
  4. Создайте EC2 key pair.
    Скачайте .pem файл и сохраните его локально, например в ~/.ssh/keyflow-gpu.pem.
  5. Создайте security group.
    Откройте входящий TCP 22 и TCP 8080 только для вашего IP или безопасного диапазона.
  6. Настройте AWS profile локально.
    Если удобнее через CLI, выполните:
aws configure --profile keyflow

Либо введите credentials прямо в диалоге программы по кнопке Настроить credentials....

  1. Откройте Settings → Cloud (AWS).
    Заполните поля AWS Profile, Region, SSH ключ и SSH user.
  2. Откройте Менеджер инстансов.
    Там находятся AMI, key pair, security group, выбор Spot/On-Demand и список текущих инстансов.
  3. Если своего AMI ещё нет, используйте 1-клик: создать GPU.
    Программа попытается:
  • найти публичный Ubuntu 22.04 GPU AMI,
  • взять g5.xlarge,
  • запустить его как Spot,
  • создать диск gp3 60 GB,
  • подставить выбранные key pair и security group.
  1. Дождитесь состояния Running и выберите инстанс.
    Можно сделать двойной клик по инстансу в списке — Instance ID и IP подставятся автоматически.
  2. Нажмите Проверить окружение.
    Программа сначала делает SSH-проверку. Если worker, venv, зависимости или модели не готовы, появится предложение установить всё автоматически. Согласитесь.
  3. Дождитесь bootstrap worker.
    В этот момент приложение:
  • копирует cloud worker bundle по SSH,
  • создаёт или обновляет ~/keyflow-venv,
  • ставит Python-зависимости,
  • скачивает модели MatAnyone2, BiRefNet и GVM,
  • запускает worker на порту 8080,
  • проверяет /health.
  1. После первого успешного запуска создайте свой AMI.
    В менеджере инстансов: правый клик по инстансу → Создать AMI. После этого повторные запуски будут намного быстрее, потому что worker и модели уже будут внутри вашего образа.
  2. Опционально установите watchdog.
    Он автоматически выключит инстанс, если GPU долго простаивает. Это полезно, чтобы не забывать дорогой инстанс включённым.
  3. Включите флажок Cloud GPU и работайте из программы как обычно.

Как работать потом, когда всё уже настроено

  1. Открыть Cloud (AWS) настройки.
  2. Нажать Запустить или выбрать инстанс в менеджере и стартовать его.
  3. Дождаться Running и актуального IP.
  4. При необходимости нажать Проверить окружение, если локальный bundle обновился.
  5. Запускать задачи из основного окна.
  6. После завершения работы остановить инстанс кнопкой Остановить или положиться на watchdog.

Как поля в программе соотносятся с AWS

Поле в программе Что это значит
AWS профиль Имя профиля из ~/.aws/credentials или из диалога credentials внутри программы.
Регион Регион EC2, где находится инстанс, key pair, security group и AMI.
Instance ID Идентификатор EC2-инстанса, например i-0123456789abcdef0.
SSH ключ Локальный путь к вашему .pem файлу.
SSH user Обычно ubuntu для Ubuntu/DLAMI. Для Amazon Linux это часто ec2-user.
AMI AMI, из которого будут запускаться новые инстансы в менеджере.
EC2 key pair Имя key pair в AWS, которое будет привязано к новому инстансу.
Security group SG, который откроет SSH и HTTP API worker.
IP / hostname Публичный адрес worker. Обычно заполняется автоматически, но можно ввести вручную.

Ограничения и важные оговорки

  • Spot может быть прерван. Если инстанс Spot будет забран AWS, текущая задача прервётся. Для стабильной работы используйте On-Demand.
  • Worker обрабатывает только одну задачу одновременно. Это сознательное ограничение из-за GPU-памяти.
  • Порт 8080 должен быть доступен. Без этого облачная обработка не сможет связаться с worker даже если SSH работает.
  • Terminate удаляет root EBS. Инстанс создаётся с DeleteOnTermination=True, поэтому не храните уникальные данные только на локальном диске инстанса. Для долгосрочного хранения используйте AMI, snapshot или скачивайте результаты.
  • Старые пользовательские AMI не удаляются автоматически. Периодически чистите ненужные образы и snapshot'ы, чтобы не копились расходы.
  • Quick create рассчитан на Ubuntu 22.04 GPU AMI. Поэтому SSH user по умолчанию должен быть ubuntu.

Если что-то не работает

Не показываются расходы

  • Проверьте, что Cost Explorer активирован.
  • Проверьте права ce:GetCostAndUsage и ce:GetCostForecast.

Список GPU-инстансов пустой или странный

  • Проверьте квоты G/VT для Spot и On-Demand.
  • Проверьте, что в регионе действительно предлагаются G5/G6.

AMI не находится автоматически

  • Попробуйте другой регион.
  • Выберите AMI вручную через список.
  • После первого успешного bootstrap создайте свой AMI и дальше используйте его.

SSH проходит, а облачная задача не стартует

  • Проверьте inbound rule на TCP 8080.
  • Нажмите Проверить окружение и дождитесь успешного health check.

Не удаётся подключиться по SSH

  • Проверьте, что выбран правильный .pem файл.
  • Проверьте security group на порт 22.
  • Для Ubuntu используйте ubuntu, для Amazon Linux — ec2-user.
