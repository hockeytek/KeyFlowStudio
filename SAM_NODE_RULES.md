# Правила Подключения Ноды SAM2 Mask

## Назначение

Этот документ фиксирует правила для ноды **SAM2 Mask** в KeyFlow Studio и разделяет:

- факты из оригинального GitHub-проекта авторов
- наши локальные правила интеграции в KeyFlow Studio

Цель: чётко зафиксировать семантику портов, режимы работы и место ноды в пайплайне.

---

## Источники (Проверено по GitHub Авторов)

Актуальная версия SAM 2 (Segment Anything in Images and Videos):

- https://github.com/facebookresearch/sam2

Проверенные факты из репозитория авторов:

- SAM2 — расширяет SAM на видео через `SAM2VideoPredictor`; поддерживает и одиночные изображения.
- Типы промптов: click-точки (foreground=1 / background=0), bounding box.
- Авторский `predictor.predict()` возвращает до 3 масок-кандидатов при `multimask_output=True`; лучшая выбирается по `scores`.
- При `multimask_output=False` возвращается одна маска.
- Рефайн-пасс: передача лучшего low-res logit обратно в predict как `mask_input` улучшает точность границ — документировано в авторских notebooks.
- SAM не является monocular alpha matting-моделью: результат — бинарная маска, не плавный alpha-matte.

Важно:

- В KeyFlow Studio нода SAM2 Mask работает в SAM2-режиме.
- Для связки с CorridorKey в видео-сценарии используется SAM2, так как нужен трекинг и масочная секвенция.

## Статус Совместимости (Важно)

- Для CorridorKey в видео-сценарии нода SAM2 Mask считается корректно поддержанной только при работе в режиме SAM2.
- Если требуется подать alpha hint в CorridorKey из SAM2 Mask, рабочий контракт: SAM2 + подготовленная маска + propagation по диапазону.

---

## Что Является Контрактом В Нашем Проекте (Локальная Интеграция)

По нашей нодовой спецификации (`app/node_graph/specs/sam_mask.py`):

- Вход SAM2 Mask:
  - `img` (тип `image`, required)
- Выход SAM2 Mask:
  - `out` (тип `alpha`, отображаемое имя порта: `mask`)

Семантика в KeyFlow Studio:

- `img` = RGB-кадр для интерактивной разметки
- `mask` = бинарная маска (0/255), граница объекта по кликам

---

## Правила Входного Порта

### Вход `img`

- Принимает только `image`-поток
- Ожидается RGB-кадр или первый кадр последовательности

Рекомендуемые источники:

- `Source` (нода загрузки медиа)
- `Load`
- любая upstream-нода с корректным RGB output

Не подключать:

- маски / alpha — порт img семантически является RGB-входом
- EXR linear float данные без явного приведения к sRGB

---

## Правила Выходного Порта

### Выход `mask`

- Тип: `alpha`
- Формат: бинарная маска uint8 (0 = фон, 255 = объект)
- Это **не** финальный matte; это одиночная бинарная маска для выбранного кадра

Ограничение для видео-пайплайна:

- CorridorKey принимает alpha-hint как секвенцию кадров, длина которой должна совпадать с длиной входного image-потока.
- В этой связке одиночная маска недостаточна: нужна масочная последовательность по выбранному диапазону.
- Рабочий режим: SAM2 формирует секвенцию масок (tracking), после чего она подается в CorridorKey.

Дополнительно:

```
SAM2 Mask.mask -> Write  — для сохранения промежуточной маски
```

## Интерактивный Рабочий Процесс

SAM2 Mask работает в режиме ручной разметки одного опорного кадра:

1. Пользователь кликает на input viewer — точки накапливаются в `SamRuntimeState`.
2. При нажатии **Generate** или в режиме Auto SAM2:
   - кадр и точки отправляются в `SamMaskWorker` в отдельном QThread
   - вызывается `SamService.generate_mask(image_rgb, points, labels)`
   - predictor выполняет первый pass (`multimask_output=True`) → возвращает 3 кандидата
   - при `auto_refine=True` — второй refinement pass с лучшим logit как `mask_input`
   - опциональный fallback: auto bbox из первой маски → ещё один pass
   - возвращается лучший результат как `uint8 * 255`
3. Маска отображается в правом viewer.
4. Пользователь нажимает **Add** — маска добавляется в список.
5. При запуске CorridorKey все добавленные маски объединяются (logical OR) и сохраняются во временный PNG.

## Инструкция Для Связки SAM2 Mask -> CorridorKey

Ниже описан рабочий порядок именно для связки SAM2 Mask и CorridorKey в видео:

1. В ноде SAM2 Mask должен быть включен режим SAM2.
2. В интерфейсе задается диапазон кадров обработки (start/end или count).
3. На опорном кадре подготавливается минимум одна корректная маска (по кликам/промптам).
4. Запускается процедура трекинга SAM2 вперед по диапазону, чтобы получить масочную секвенцию на все кадры выбранного диапазона.
5. При запуске общего процесса SAM2 сначала формирует полный alpha-hint диапазона, затем выгружается из памяти.
6. После этого CorridorKey выполняет свою стадию, читая уже подготовленную секвенцию масок.

Почему процесс выполняется последовательно:

- И SAM2, и CorridorKey загружают тяжелые веса моделей.
- Одновременное удержание обеих моделей в памяти приводит к лишнему расходу RAM/VRAM и замедлению.
- Поэтому в этой связке принят staged-подход: сначала SAM2, затем CorridorKey.

Это тот же принцип, который уже используется в связке BiRefNet -> CorridorKey.

Общее правило CorridorKey:

- До старта CorridorKey должна быть сформирована маска (alpha-hint) той нодой, которая является источником alpha.
- Количество кадров в alpha-hint должно совпадать с количеством кадров на входе Image CorridorKey в выбранном диапазоне.
- При несовпадении длины CorridorKey останавливает запуск с ошибкой валидации.

## Свойства Ноды SAM2 Mask

| Свойство | Тип | Описание |
|---|---|---|
| `model_type` | str | Выбор чекпоинта: `vit_h` / `vit_l` / `vit_b` |
| `auto_refine` | bool | Двухпасровый refinement через logit feedback (рекомендуется `True`) |
| `multimask` | bool | `multimask_output=True` — 3 кандидата с выбором лучшего по score |
| `live_sam` | bool | Автогенерация маски на каждый клик |
| `point_mode` | str | `"positive"` (объект) или `"negative"` (фон) |
| `clear_points_before_run` | bool | Очищать накопленные точки перед каждым запуском |

## Доступные Чекпоинты (SAM2)

| Модель | Размер | Файл |
|---|---|---|
| `vit_h` | Large | `sam2.1_hiera_large.pt` |
| `vit_l` | Base+ | `sam2.1_hiera_base_plus.pt` |
| `vit_b` | Small | `sam2.1_hiera_small.pt` |

Чекпоинты скачиваются автоматически из `https://dl.fbaipublicfiles.com/segment_anything_2/`.
Локальные веса сохраняются в пользовательской директории моделей KeyFlow Studio
(по умолчанию на macOS: `~/Library/Application Support/com.keyflow.studio/models`).

## Управление Памятью (VRAM)

- SAM2 загружается лениво (при первой генерации/трекинге маски).
- Перед запуском инференса CorridorKey/MatAnyone2 SAM2 выгружается из памяти.
- После выгрузки предикторы инициируются повторно при следующем запуске.
- Это критично для CPU/MPS устройств с ограниченной RAM.

---

## Роль SAM2 Mask В Связке С CorridorKey (Локальная Архитектура)

Рекомендуемая схема:

```
Source/Load -> SAM2 Mask.img
SAM2 Mask.mask -> CorridorKey.Alpha Hint
Source/Load -> CorridorKey.Image
```

Смысл:

- В режиме SAM2 нода SAM2 Mask формирует alpha-hint секвенцию в выбранном диапазоне
- Эта секвенция подается в CorridorKey как вход Alpha Hint
- Далее CorridorKey выполняет основной проход по Image с уже готовым alpha-hint

---

## Что Нельзя Путать

- `SAM.mask` (тип `alpha`) ≠ `CorridorKey.Processed` (финальный matte с плавными краями)
- `SAM.mask` (тип `alpha`) ≠ секвенция alpha-hint для CorridorKey
- SAM не выполняет alpha matting; он сегментирует — граница резкая, бинарная
- `img` порт — это RGB, не маска; подача маски в `img` испортит сегментацию
- Режим Auto SAM2 не взаимодействует с SAM2 video propagation; это только для разметки одного кадра

---

## Краткая Памятка

- `SAM.img` = исходный RGB-кадр для разметки
- `SAM.mask` = бинарная маска (0/255) по объекту из кликов
- Для CorridorKey в видео использовать SAM2 Mask только в режиме SAM2 с генерацией секвенции
- Для диагностики по-прежнему допустим downstream `SAM.mask -> Write`
- Refinement `auto_refine=True` — всегда включать для лучшего качества границ
- SAM выгружается из памяти автоматически перед запуском обработки видео
